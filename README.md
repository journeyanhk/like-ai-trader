# AI 交易智能体

以「模拟交易优先」为原则的 AI 交易系统：**研究由 AI 提出假设，风控和执行由确定性代码完成，AI 永远不直接下单。**

- 市场：OKX 永续合约（BTC、ETH、SOL、XRP、DOGE，均为 USDT 本位）
- 周期：1h 主周期，4h 确认周期
- 模式：PAPER（模拟），真钱模式需全部验收通过后才开放

设计文档见 [`docs/design-doc.md`](docs/design-doc.md)，建设计划见 [`docs/plan.md`](docs/plan.md)。

## 市场状态规则（确定性）

| 状态 | 规则 | 允许策略 |
|---|---|---|
| 上涨/下跌趋势 | ADX(14) > 25 且 1h、4h EMA20 斜率同向 | 趋势突破（主力）；趋势跟随（旧，默认关闭） |
| 震荡 | ADX(14) < 20 | 均值回归（旧，默认关闭） |
| 高波动 | ATR(14)/价格 ≥ 过去 90 天 80 分位 | 不开新仓 |
| 低流动性 | 24h 成交量 < 30 日均值 50%，或价差 > 0.05% | 不开新仓 |
| 不明确 | 其余情况 | 不开新仓 |

判断顺序：低流动性 → 高波动 → 趋势 → 震荡 → 不明确。

## 策略（第 7 次交付）

**主力策略：趋势突破（breakout v1.0）**
- 入场：1 小时收盘价突破过去 N 小时（默认 120）最高价、且在 200 小时均线上方 → 做多；反之做空。只在「上涨/下跌趋势」状态下开仓。
- 离场：只用 ATR 移动止损（默认 4 倍 ATR），不设固定止盈，让盈利奔跑。
- 滚动验证时 N 在 96/120/168、ATR 倍数在 3/4/5 中由训练期选出。

**为什么换：** 旧的「趋势跟随」「均值回归」在 2 年回测里都亏钱（样本外夏普 -1.4~-2.2）。研究比较了十几种方案：
- 短线回调/均值回归类：扣除手续费和滑点后全部亏损；
- 突破类：所有变体样本外都为正（夏普 0.5~1.2），说明优势不是偶然调参调出来的；
- 只做 BTC/ETH 时夏普约 0.6~1.2，扩到 5 个币后更稳定（分散）。

**回测 #4 结果（5 个币，市场状态过滤开，2024-11 ~ 2026-10）：** 样本外夏普 1.21、回撤 12.3%、269 笔、覆盖涨跌震荡、参数 ±20% 稳定 → 5/5 通过。

**需要知道的风险：**
- 样本外有连续两个月各亏约 7%（回撤 12.3%），实盘规则下会触发 10% 回撤锁定、需要人工解锁；
- 5 个币里 BTC 单独是小亏的，盈利主要来自 XRP、ETH、SOL、DOGE；
- 这是在同一段历史上比较多个方案后选出的，真实表现大概率比回测差一些，所以还要靠 30 天模拟盘检验。

## 回测规则

- 信号在 K 线收盘时产生，下一根 K 线开盘成交（不偷看未来）
- 成本：吃单手续费 0.05% + 滑点 5bp；资金费用 OKX 真实历史（已回填 730 天，REST 接口只有约 3 个月，更早的从 OKX 官方月度文件补齐；重叠部分逐条核对一致）
- 止损：按 K 线最低 / 最高价触发，成交价 = 止损价；开盘就跳空越过止损则按开盘价
- 数量按 OKX 合约规格取整（每张 ctVal 个币，步长 lotSz，最小 minSz 张），只向下取整；不足最小下单量则不交易并记录原因
- **留出集**：2026-07-11 起的最近 90 天（边界固定）不参与任何策略比较或参数挑选，留到最终一次性检验
- 每笔风险 0.3% 净值（设计文档上限 0.5%，第 7 次交付在设置页调低并留有记录），单日亏损 2% 当日停开新仓，可选 10% 回撤锁定
- 滚动验证：训练窗口网格搜索最优参数（夏普最大、至少 8 笔交易），在随后的测试窗口上检验；样本外曲线由不重叠测试段拼接
- 验收线：样本外夏普 > 1、最大回撤 < 15%、交易 > 100 笔、覆盖涨/跌/震荡行情、参数 ±20% 不崩溃
- 回测完全在本地计算，不消耗 Surf 点数

## 模拟交易与风控（PAPER）

每小时第 2 分钟：同步行情 → 判定市场状态 → 只运行允许的策略 → 风控逐项审核 → 模拟成交（本小时 K 线开盘价 + 5bp 滑点，扣 0.05% 手续费）。
每分钟：风控巡检。**AI 不参与任何下单决定。**

| 红线 | 规则 | 处理 |
|---|---|---|
| 单笔风险 | 权益 0.3%（上限 0.5%），仓位 = 风险金额 / 止损距离 | 自动计算 |
| 敞口 | 单币 ≤ 50%，5 个币同属一个相关组、合计 ≤ 60%，总敞口 ≤ 100%，杠杆 ≤ 3x | 超出部分自动裁剪 |
| 日亏 | 当日（UTC）亏损 ≥ 2%（K 线收盘时判断） | 当日停开新仓，次日自动恢复 |
| 回撤 | 从峰值回撤 ≥ 10%（K 线收盘时判断） | 下一根开盘全部平仓并锁定，需人工解锁 |
| 策略失效 | 累计 ≥ 20 笔 且 运行 ≥ 30 天后，最近 20 笔盈亏比 < 1.0 | 策略自动下线 |
| 紧急停止 | 网页按钮 | 立即平掉全部持仓，停止开新仓，人工恢复 |

自动暂停条件（只拦开新仓，止损照常）：

| 条件 | 恢复方式 |
|---|---|
| 行情数据过期 > 60 秒 | 连续 5 次检查正常后自动恢复 |
| 合约价与指数价偏差 > 0.5% | 同上 |
| 连续接口错误 ≥ 5 次 | 同上 |
| 订单状态超过 30 秒未知 | 人工恢复（按持仓表对账处理未知订单） |
| 持仓表与订单账本对账不一致 | 人工恢复 |

其他：每个订单带唯一 clientOrderId（同一信号重复执行也只下一次单）；启动即对账；心跳每 5 分钟，连续缺 3 次在下次启动时告警；整点任务错过会在 5 分钟后自动补跑（补跑时按实时价成交）。

其他补充：行情过期暂停期间，每分钟巡检仍用最近一次有效价格判断止损，止损保护不中断。

### 回测与模拟盘同一引擎（第 8 次交付）

- `backend/lib/simulate.js` 是唯一的撮合与记账实现：开仓、止损、资金费结算、仓位计算（`risk.sizePosition`）、合约取整都只在这里。`backtest.js` 和 `paper.js` 只是驱动它。
- 时间顺序统一：每个整点先结算资金费（只结已持有的仓位）→ 执行离场 → 执行上一根收盘产生的开仓信号；收盘时判断止损、日亏、回撤并产生下一根的信号。
- 模拟盘指标用与回测相同长度的历史（从开始时间往前 730 天的固定锚点算起）。

| 检查 | 命令 | 要求 |
|---|---|---|
| 等价性 + 确定性 | `cd backend && node tests/equivalence.test.js 60` | 同一段 60 天历史，回测与模拟盘主循环 fills 逐笔一致；cash / realized_pnl / funding_pnl / fees_paid / unrealized / equity 差值为 0；两次运行 sha256 相同；复现包重跑也一致 |
| 资金费对账 | `node tests/funding-audit.test.js` | 三笔资金费的 qty / mark / rate / cashflow 与 OKX 历史一致 |
| 单元测试 | `npm test`（全部：单元 + 等价性 + 资金费对账 + 演练） | 仓位、合约取整、相关组上限、策略失效、状态机等 |
| 演练 | `node scripts/paper-drill.js` | 用历史回放驱动真实主循环（内存账户，不碰正式账户），覆盖止损、暂停、紧急停止、未知订单、回撤锁定、日亏 |
| 合约规格 | `node scripts/check-contracts.js` | 配置里的 ctVal/lotSz/minSz 与 OKX 实时规格一致；每日复盘任务（UTC 00:05）也自动核对，变化即告警 |
| 资金费回填 | `node scripts/backfill-funding.js` | 回填至少 400 天（默认 730 天） |
| 重置模拟账户 | `node scripts/paper-reset.js "原因"` | 清空模拟账户并重新计时，同时生成新的复现包 |

**复现包**：模拟账户开始时写入 `paper_repro` 表：配置哈希、引擎代码哈希、git commit、candles 与 funding_rates 表的行数和首尾时间、调用参数。验收页的「同期回测」只用复现包里的参数和配置重跑，并核对启动前的历史数据没有被改动。

### 告警与探活

- **Telegram 直发**：在 `backend/.env` 填 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID`。自动暂停 / 恢复、开平仓、止损、回撤锁定、日亏、紧急停止、对账异常、自检异常都会推送（同一条 10 分钟内不重复，每小时最多 30 条）。设置页可发测试消息。
- **外部探活（拉取）**：`GET /api/probe`，正常 200、异常 503。用 UptimeRobot 等外部服务每几分钟访问一次；系统整个挂掉时由外部服务提醒你。
- **外部探活（推送，可选）**：在 `backend/.env` 填 `HEALTHCHECK_PING_URL`（如 Healthchecks.io），每分钟巡检成功就报一次平安，超时未报由对方告警。

已接通（第 9 次交付）：Telegram 群（chat_id 为负数，是群组）与 Healthchecks.io 推送探活，令牌只存在 `backend/.env`，不进 git。`.env` 改动无需重启，下一次巡检自动读到。

### 已知运营风险

- **回撤锁定大约一年触发一次。** 回测 #5 的样本外最大回撤 10.06%，而运行规则是「回撤 ≥ 10% 全平并锁定、人工解锁」。验收线是 < 15%，所以验收能过，但按历史推算，真实运行中大约每年会触发一次锁定，需要人工检查后解锁。我们**选择维持 10%**（宁可多停一次，也不放宽亏损上限），把这次人工介入当作正常运营的一部分，而不是故障。
- **止损成交价偏乐观（已记入下一轮冻结前待办）。** 当前止损按止损价成交、没有额外滑点（`stopSlippageBps` 未配置，默认 0），比普通市价单（5 bp）还理想；快速行情里真实止损通常更差。计划在下一轮参数冻结前把 `costs.stopSlippageBps` 设为 10。**30 天模拟盘计时期间不改**，因为它属于冻结的成本参数，改了会让模拟盘与复现包不一致。

## AI 复盘（第 5 次交付）

- **边界**：所有数字由代码计算；AI 只把数字写成中文点评和「待验证的改进点」。AI 输出只存档，**不进入下单流程**。
- **每日复盘**：每天 UTC 00:05（北京时间 08:05）自动生成前一天的复盘；也可以手动生成 / 重新生成（保留历史版本）。
- **市场解读**：手动点按钮调用，每天最多 5 次。
- **费用保护**：所有 AI 调用每天最多 10 次；本月估算花费超过 3 美元自动停止；没有 Key 或调用失败时照样保存数字部分。
- **新闻**：设置页开关，默认关闭；开启后每份复盘调用 1 次 Surf 新闻接口，消耗的点数记录在该复盘上。
- **配置**：在「设置」页填写 DeepSeek API Key（保存前自动验证，记录里只显示打码）并选择模型；也可以在 `backend/.env` 写入 `DEEPSEEK_API_KEY=...` 作为备用（该文件不会提交到 GitHub）。网页设置优先。

## 验收清单（第 6 次交付）

全部打勾之前，系统不提供真钱模式（目前代码里也没有任何真实下单功能）。

| 组 | 检查项 | 数据来源 |
|---|---|---|
| 回测 | 样本外夏普 > 1、样本外回撤 < 15%、样本外交易 > 100、覆盖涨跌震荡、参数 ±20% 不崩塌 | 选定的一次回测（默认最新） |
| 模拟 | 连续运行 ≥ 30 天（心跳连续缺失 15 分钟以上算中断，从中断后重新计） | 启动事件里的心跳间隔 |
| 模拟 | 无未处理异常（非停止/锁定、无暂停、无未知订单、对账一致、心跳正常） | 实时状态 |
| 模拟 | 模拟净值与同期回测偏差 < 20%：\|模拟收益 − 回测收益\| ÷ max(\|回测收益\|, 1%)，满 30 天才计入 | 用相同策略/风控/成本在同一时段跑回测 |
| 暂停 | 5 个自动暂停条件各触发并处理过至少一次（真实或「故障演练」都算） | 事件流水 |
| 实盘 | 首期资金 ≤ 总资金 5% | 配置 `live.maxInitialCapitalPct` |

故障演练：只能在每小时第 8–50 分钟进行，一次一个；自动类条件由巡检连续 5 次正常后自动恢复，人工类需要在模拟交易页点「恢复运行」。

## 自行部署

本项目基于 Surf SDK（Node.js + Express 后端，Vite + React 前端，Postgres 数据库）。

1. 安装 [Bun](https://bun.sh) 或 Node.js 20+
2. `cd backend && bun install`，`cd frontend && bun install`
3. 环境变量：
   - 行情无需任何密钥（OKX 公共接口）；注意 OKX 在部分地区受限，服务器需选在可访问的地区
   - 数据库连接目前由 Surf SDK 管理（见 `@surf-ai/sdk/db`），自行部署时需替换为自己的 Postgres
4. 启动后端：`cd backend && node server.js`；构建前端：`cd frontend && bun run build`
5. 定时任务由后端进程内置调度，进程需 7×24 在线（建议用 systemd / Docker / pm2 守护）

> 密钥只通过环境变量提供，切勿提交 `.env` 文件。
